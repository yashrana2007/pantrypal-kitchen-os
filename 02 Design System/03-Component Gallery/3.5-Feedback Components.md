3.5 Feedback Components

Project: Evergreen

Version: 1.0 Alpha

Status: 🟡 In Review

3.5.1 Purpose

Feedback Components communicate system status, confirm user actions, explain errors, and guide users through ongoing processes.

They should reassure users without interrupting their workflow.

Feedback should always be:

Timely
Clear
Helpful
Calm
3.5.2 Feedback Philosophy

Feedback should answer one question:

"What just happened?"

It should never create unnecessary stress.

3.5.3 Component Family
Component	Purpose
Success Toast	Confirms completed actions
Info Toast	Provides neutral updates
Warning Banner	Draws attention
Error Banner	Explains problems
Success Banner	Celebrates completion
Loading Spinner	Short loading tasks
Skeleton Loader	Long loading tasks
Empty State	No available content
Confirmation Dialog	Prevents destructive actions
Offline Banner	Network unavailable
3.5.4 Success Toast
Purpose

Confirms successful actions.

Examples

✓ Ingredient Added

✓ Kitchen Updated

✓ Grocery Saved

✓ Smart Add Completed

Duration:

2–3 seconds

Position:

Bottom of the screen

3.5.5 Information Toast

Used for informative updates.

Examples:

Kitchen synchronized.

Recipe imported.

Analysis completed.

3.5.6 Warning Banner

Purpose

Draw attention without causing anxiety.

Examples:

Milk expires tomorrow.
Pantry is running low.
Protein intake is below today's goal.

Yellow semantic color.

Dismissible.

3.5.7 Error Banner

Purpose

Explain what went wrong and how to recover.

Example:

We couldn't connect to the internet.

Try again when you're back online.

Always provide a recovery action.

3.5.8 Success Banner

Used for larger achievements.

Examples:

Weekly Goal Completed
Zero Food Waste This Week
Pantry Organized

Should remain celebratory but subtle.

3.5.9 Loading Spinner

Purpose

Indicates short processing tasks.

Used only when loading is expected to take less than three seconds.

3.5.10 Skeleton Loader

Preferred over spinners for content loading.

Examples:

Loading Kitchen
Loading Recipes
Loading Analytics

Skeletons preserve layout stability and improve perceived performance.

3.5.11 Empty State

Every Empty State should include:

Friendly illustration
Positive message
Clear action

Example:

Your pantry is ready for its first ingredient.

Add an item to begin building your kitchen.

3.5.12 Confirmation Dialog

Reserved only for important actions.

Examples:

Delete ingredient
Clear pantry
Remove grocery list

Every confirmation should explain the consequence before the user confirms.

3.5.13 Offline Banner

Displayed when PantryPal cannot synchronize.

Example:

You're offline. We'll sync everything automatically when your connection returns.

No action required from the user.

3.5.14 Component States

Every feedback component supports:

Visible
Hidden
Dismissed
Auto-dismiss (where applicable)
3.5.15 Accessibility

Feedback should:

Be announced by screen readers.
Remain visible long enough to read.
Never rely only on color.
Include icons where appropriate.
3.5.16 Tone of Voice

Feedback should always sound supportive.

Good:

Ingredient added successfully.

You're all set.

We saved your changes.

Avoid:

Success.

Error 504.

Invalid Operation.

3.5.17 Motion

Feedback should appear smoothly.

Recommended:

Fade + Slide
200–300 ms
Soft easing

Never bounce or flash.

3.5.18 Evergreen Principle

Good feedback builds confidence. Great feedback builds trust.
