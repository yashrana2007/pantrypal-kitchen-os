3.3 Card Architecture

Project: Evergreen

Version: 1.0 Alpha

Status: 🟡 In Review

3.3.1 Purpose

Cards are the primary building blocks of the PantryPal interface.

Rather than displaying isolated information, each card should represent a single meaningful piece of the kitchen ecosystem.

Cards provide structure, improve readability, and allow users to scan information quickly without feeling overwhelmed.

3.3.2 Card Philosophy

Every PantryPal card should answer one question only.

Examples:

Is my kitchen ready?
What's inside my fridge?
What should I cook today?
Which ingredient needs attention?
Where can I save money?

If a card attempts to answer multiple unrelated questions, it should be divided into separate cards.

3.3.3 Design Principles

Every card should feel:

🌿 Calm

🏡 Friendly

✨ Spacious

💚 Trustworthy

📖 Easy to Scan

Cards should never resemble miniature dashboards.

Instead, they should present one clear piece of information.

3.3.4 Card Anatomy

Every PantryPal card follows a consistent structure.

┌─────────────────────────────┐
│ Icon / Status               │
│                             │
│ Title                       │
│                             │
│ Primary Information         │
│                             │
│ Supporting Information      │
│                             │
│ Action (Optional)           │
└─────────────────────────────┘

This structure should remain consistent across all card types.

3.3.5 Card Grid System

PantryPal uses five standardized card sizes.

Card Type	Width	Height	Usage
Hero	Full	Large	Kitchen Ready
Feature	Half	Medium	Kitchen Zones
Standard	Full	Medium	Planner
Compact	Half	Small	Statistics
List	Full	Compact	Ingredient Lists

No custom card sizes should be introduced without updating the Design System.

Component	Radius

3.3.9 Typography Hierarchy

Every card follows this order.

Title
Primary Data
Supporting Data
Caption

Never introduce additional hierarchy levels unless necessary.

3.3.10 Card States

Every interactive card supports:

Default
Hover
Pressed
Loading
Disabled
Empty

Animations should use Motion Tokens.

3.3.11 Action Placement

Actions should always appear in predictable locations.

Preferred order:

Bottom Right

↓

Bottom Center

↓

Entire Card Clickable

Avoid placing buttons in inconsistent positions.

3.3.12 Information Density

Cards should prioritize simplicity.

Rule:

Maximum:

One title
One primary value
Two supporting values
One action

If additional information is required, open a Bottom Sheet.

3.3.13 Empty Cards

Empty cards should guide users rather than display blank spaces.

Example:

Your pantry is empty.

Add your first ingredient to begin tracking your kitchen.

Every empty card should include:

Friendly illustration
Helpful explanation
Primary action
3.3.14 Loading Cards

Instead of spinners, PantryPal should use skeleton placeholders.

Benefits:

Better perceived performance
Stable layouts
Less visual disruption
3.3.15 Accessibility

Cards should:

Maintain readable typography
Support screen readers
Use sufficient contrast
Avoid information overload
Provide clear tap targets
3.3.16 Card Composition Rules

Do:

Keep one clear purpose.
Maintain generous whitespace.
Use consistent padding.
Prioritize scanability.

Don't:

Overcrowd information.
Add unnecessary decorations.
Use inconsistent heights.
Nest cards inside cards.
3.3.17 Component Relationships

Cards work together with:

Buttons
Chips
Progress Rings
Bottom Sheets
Search
Navigation

Every card should reuse existing Design System components.

3.3.18 Why This Matters

Cards are the visual language of PantryPal.

They organize information, reduce cognitive load, and create a consistent experience across every screen.

A well-designed card system allows PantryPal to scale without sacrificing clarity.

3.3.19 Living Cards

Status: 🟢 Approved (Core Design Principle)

Purpose

Living Cards are interactive UI components that subtly adapt to the user's environment and kitchen state.

Unlike traditional static cards, Living Cards create a sense of warmth, continuity, and personality without distracting from the primary content.

Their purpose is to strengthen the emotional connection between users and their digital kitchen.

Philosophy

Living Cards should never feel animated for the sake of animation.

Every visual change should represent something meaningful.

The user should subconsciously feel that the kitchen is alive.

Environmental Adaptation

Living Cards respond to:

🌅 Time of Day
Morning → Soft warm sunlight
Afternoon → Neutral daylight
Evening → Warm ambient lighting
Night → Soft dark ambience
🌦 Weather
Sunny → Bright highlights
Rain → Gentle rain visible through the kitchen window
Snow → Soft snowy background
Cloudy → Slightly muted lighting

Weather effects should remain extremely subtle.

🍂 Seasons
Spring → Fresh greenery
Summer → Bright vibrant colors
Autumn → Warm earthy accents
Winter → Cozy lighting
🎉 Festivals

Supported seasonal themes may include:

Christmas
Diwali
Halloween
New Year
Eid
Holi

Decorations should remain tasteful and optional.

Kitchen Health Response

Cards also respond to the current state of the kitchen.

Healthy Kitchen
Bright environment
Healthy indoor plants
Fresh ingredients visible
Clean counters
Running Low
Slightly emptier shelves
Suggestion badges appear
Needs Attention
Less vibrant environment
More visible empty storage
Smart Suggestions become more prominent

The interface should guide users without creating guilt or anxiety.

Motion Guidelines

Environmental transitions should be:

Smooth
Slow
Non-distracting

Recommended duration:

600–1000 ms

There should never be sudden visual changes.

Performance Rules

Living Cards should never compromise performance.

If device performance is limited:

Reduce animation frequency
Simplify environmental effects
Preserve interaction speed

Performance always takes priority over decoration.

Accessibility

Users should have complete control.

Settings:

Enable Living Cards
Reduce Motion
Disable Seasonal Decorations

Accessibility preferences always override decorative effects.

Evergreen Rule

Living Cards should enhance understanding, not compete for attention.

The content remains the focus.

The atmosphere quietly supports it.

Examples
Kitchen Ready Hero Card

Morning

Warm sunlight enters from the window.

The progress ring glows softly.

Fridge Card

The fridge illustration becomes fuller or emptier depending on inventory.

Pantry Card

Shelves gradually fill as groceries are added.

Smart Suggestion Card

A tiny sprouting leaf animation appears when the user reduces food waste.

Analytics Card

Confetti is never used.

Success is celebrated with subtle visual refinement instead.

Future Expansion

The Living Card system is designed to evolve.

Future enhancements may include:

Interactive windows
Smart home integration
Weather synchronization
Dynamic backgrounds
Personalized themes
Family personalization
🌿 Evergreen Principle

A living interface doesn't demand attention. It quietly reflects the life happening around it.
