3.4 Navigation System

Project: Evergreen

Version: 1.0 Alpha

Status: 🟢 Approved

3.4.1 Overview

The Navigation System defines how users move throughout PantryPal.

Rather than exposing complex navigation structures, PantryPal prioritizes calm, predictable, and contextual navigation that minimizes cognitive effort.

Navigation should always support the user's task without becoming the focus of attention.

3.4.2 Navigation Philosophy

Navigation should feel invisible.

Users should instinctively know where they are, where they can go next, and how to return.

Every navigation pattern must reinforce PantryPal's principles of simplicity, accessibility, and continuity.

3.4.3 Navigation Architecture

The PantryPal Navigation System consists of the following components:

Component	Purpose
Bottom Navigation	Primary app navigation
Bottom Sheet	Contextual information and actions
Toast	Lightweight feedback
Confirmation Dialog	Critical confirmations
Floating Action Button	Primary creation action
Search Bar	Global search
Context Menu	Item-specific actions
Notification Banner	Important notices
Inline Tabs	Section switching
Segmented Control	View switching
Back Navigation	Context recovery
Pull to Refresh	Content refresh
3.4.4 Bottom Navigation
Purpose

Provides access to PantryPal's four primary destinations.

Destinations
Home
My Kitchen
Planner
Insights
Rules
Maximum four items.
Labels always visible.
Icons remain consistent.
Never scroll horizontally.
Always accessible with one thumb.
3.4.5 Living Navigation

Bottom Navigation supports PantryPal's Living Environment.

Examples include:

Morning

Warm highlight.

Evening

Soft ambient glow.

Winter

Cool neutral accents.

Festivals

Subtle seasonal decorations.

Navigation remains functionally identical while visually adapting to the environment.

3.4.6 Bottom Sheets
Purpose

Bottom Sheets present contextual information without leaving the current screen.

Supported sizes:

Collapsed
Half Height
Full Height

Typical use cases include:

Ingredient details
Kitchen zone information
Shopping options
Planner details

Bottom Sheets are PantryPal's preferred navigation pattern over full-screen transitions.

3.4.7 Toast Messages
Purpose

Provide lightweight confirmation.

Examples:

Ingredient added successfully.
Shopping list updated.
Kitchen synchronized.
Changes saved.

Toast messages disappear automatically and never interrupt user workflows.

3.4.8 Confirmation Dialog

Reserved for actions that cannot be easily reversed.

Examples include:

Delete Ingredient
Clear Pantry
Remove Kitchen
Sign Out

Dialogs should always explain the consequences of the action.

3.4.9 Floating Action Button
Purpose

Highlights the primary creation action on a screen.

Examples:

Add Ingredient
Scan Barcode
Add Grocery

Rules:

One Floating Action Button per screen.
Never compete with a Primary Button.
Expand into related actions only when appropriate.
3.4.10 Search

Search should always remain immediately accessible.

Supports:

Ingredients
Recipes
Grocery items
Kitchen history
Analytics

Future enhancements:

Voice Search
Barcode Search
AI Search
3.4.11 Context Menu

Context Menus provide secondary actions for individual items.

Typical actions include:

Edit
Move
Add to Shopping List
Mark as Consumed
Delete

Context Menus should never replace primary interactions.

3.4.12 Notification Banner

Notification Banners communicate important information requiring user attention.

Examples:

Low stock alert
Kitchen synchronized
Shopping reminder

Banners should remain calm, informative, and dismissible.

3.4.13 Inline Tabs

Inline Tabs organize related content within a screen.

Examples:

All Items
Expiring Soon
Low Stock
Favorites

Tabs should never duplicate Bottom Navigation destinations.

3.4.14 Segmented Control

Segmented Controls switch between closely related views.

Examples:

Grid / List
Fastest / Smart / Save Money
Daily / Weekly / Monthly

Only one segment may be active at a time.

3.4.15 Back Navigation

Back Navigation always returns users to the previous context.

Unexpected jumps or resets should be avoided.

Users should always feel oriented.

3.4.16 Pull to Refresh

Provides a familiar gesture for updating content.

Refresh interactions should include subtle animation and immediate feedback.

3.4.17 Accessibility

Navigation components must support:

Minimum 48 × 48 px touch targets.
Screen reader compatibility.
Keyboard navigation (future web support).
Visible focus indicators.
High contrast labels.
3.4.18 Motion

Navigation animations should:

Reinforce orientation.
Confirm interactions.
Feel smooth and natural.

Avoid unnecessary transitions.

3.4.19 Component Relationships

Navigation components integrate with:

Cards
Buttons
Inputs
Progress Indicators
Bottom Sheets
Dialogs

Every navigation component must follow PantryPal Design Tokens.

3.4.20 Future Expansion

Future navigation enhancements may include:

Voice-first navigation
Smart contextual shortcuts
Wearable companion navigation
Smart appliance integration
Multi-device continuity
🌿 Evergreen Principle

Users should always know where they are, where they can go, and how to return—without thinking about it.
